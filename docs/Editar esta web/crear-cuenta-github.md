# Crear una cuenta de GitHub

GitHub es el sitio donde se guarda el texto de esta web. Para **leer** la web no
hace falta nada. Para **proponer cambios**, sí necesitas una cuenta, que es
gratuita y se crea en un par de minutos.

## Crear la cuenta

1. Entra en **[github.com/signup](https://github.com/signup)**.
2. Escribe tu **correo electrónico**. Te recomendamos usar tu correo de JMV
   (`...@jmvesp.org`) si lo tienes, para que se vea claro quién hace cada cambio.
3. Elige una **contraseña** y un **nombre de usuario**. El nombre de usuario será
   visible en los cambios que hagas: algo como `mariagarcia` o `jmv-sevilla` va
   bien; evita apodos que nadie pueda identificar.
4. Responde si quieres recibir novedades por correo (puedes decir que no).
5. Resuelve el pequeño puzle de verificación.
6. Introduce el **código** que GitHub te envía por correo electrónico.
7. Cuando te pregunte por planes o por el tipo de uso, **elige siempre la opción
   gratuita** (*Free*). No hace falta pagar nada para esto.

!!! success "Ya está"

    Con eso tienes cuenta. GitHub está en inglés por defecto y tiene muchísimas
    opciones que no vas a necesitar: ignóralas tranquilamente. Para esto solo
    usarás un botón y una caja de texto.

## Activa la verificación en dos pasos

GitHub pide configurar **verificación en dos pasos** (2FA). Es ese sistema por el
que, además de la contraseña, te pide un código de una app del móvil.

No lo dejes para luego: GitHub lo acaba exigiendo para poder seguir usando la
cuenta, y es preferible configurarlo con calma que a mitad de una corrección
urgente. Sirve cualquier app de autenticación (Google Authenticator, Microsoft
Authenticator, el propio gestor de contraseñas del móvil...).

## Pide acceso al repositorio

Con la cuenta creada, **avisa a alguien del equipo de webmasters** con tu nombre
de usuario de GitHub para que te dé acceso al repositorio de la asociación.

!!! info "Si no tienes acceso todavía"

    Podrás proponer cambios igualmente, pero GitHub hará antes una copia
    personal del repositorio (lo llama *fork*) y te avisará de ello. No es un
    error ni has hecho nada mal: tu propuesta llega igual a quien la revisa.
    Aun así, es más cómodo para todos tener el acceso concedido.
